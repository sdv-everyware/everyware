# Traps met while adding service bundles (2026-11-05)

| Symptom | Cause | Fix |
|---------|-------|-----|
| `vsidlc` E513 "unknown maximum size", E511 "annotation ... is missing" | a string or repeated field without a bound | `[(.sdv.vsidl.v1.variable_type_max_size) = N]`, `[(.sdv.vsidl.v1.repeated_field_max_count) = N]` |
| Soong: `Rust dependency "..." has the wrong StdLinkage; expected 3, got 2` | `prefer_rlib` on one side of a dependency only | no `prefer_rlib` anywhere in our bundles and generated crates (vsidlc's shape) |
| Soong: `depends on libsdv_comms_sd_stub which is not visible` | the FFI stubs are not for direct use | do not list `shared_libs`; `libsdv_rs` brings them |
| `dlopen failed: cannot locate symbol "ASDV_UnitRegistrationArgs_getUnitType"` (tag `ApexSupport`), the runner panics `Failed to load bundle libraries` with an empty dlerror | the bundle was linked as one object with `prefer_rlib`: the symbol resolved from the `dt` stub, `--as-needed` dropped `sd`, and on the device only the real `sd` library has it | the generated shape: Rust deps as dylibs, each with its own NEEDED (the APEX bundles the `.dylib.so` files) |
| `fetch failed: No address associated with hostname` right after boot | DHCP has no lease yet | retry every second; the bundle starts before the network |
| `CERTIFICATE_VERIFY_FAILED` on the first HTTPS calls after boot | the clock is 1970 until chrony sets it; the certificate is "not yet valid" | retry; `date` on the board shows when the clock is set |
| `generate_zip_catalog.sh` run by hand from the tree root overwrote `build/soong/root.bp` and created `sdv/` at the root ("module already defined" everywhere) | the script does `cp -r .../protos/* .` into the current directory and follows the `Android.bp -> build/soong/root.bp` symlink | never run it by hand; `git -C build/soong checkout -- root.bp`, `rm -rf <tree>/sdv`. Use `vsidlc ... --no-genrule -o <scratch>` to see generated files |
| the APEX activates but the bundle is not in `ps` | the runner crashed at load; the lifecycle agent retries later | `adb logcat -s ApexSupport <name>_bundle` |
| `/apex/com.everyware.<name>` missing after the reboot | the file is not in `/product/apex` or the manifest name differs | `deploy-bundle-rb3.sh` prints the active APEXes; `cat /apex/apex-info-list.xml` |
| a bundle's `async fn` holds `&self` across an await and `JoinSet::spawn` says "future cannot be sent" | `Publisher<T>` is not `Sync`, so a shared borrow of a struct holding it is not `Send` | own the publishers (move them into the session), make the publish fn synchronous, take `&mut self` |
| `std::os::linux::net::SocketAddrExt` not found on the device build | the target is Android | `#[cfg(target_os = "android")] use std::os::android::net::SocketAddrExt;` (and the linux one for the host) |
| `m` in the Bash tool fails with "vendor/linaro/db845c is missing" | `tools/env.sh` resolves paths differently under zsh | run the build through `bash -c '... source device/rb3/sdv_media_db845c/tools/env.sh && m ...'` |
| the supplicant's abstract socket is bound but the client gets no reply | the supplicant binds the whole `sun_path` (108 bytes): its abstract name is NUL-padded, `/proc/net/unix` shows `@wpa_everyware@@@...`; a shorter name is another socket | pad the client's destination name with NULs to 107 bytes (`wpa_ctrl.rs`) |
| `ATTACH` on the global control interface is answered with UNKNOWN COMMAND or not at all | the global interface takes ATTACH/DETACH itself, before the `IFNAME=` routing | send `ATTACH` without the prefix; events come as `IFNAME=wlan0 <3>...` |
| `wpa_cli -g@abstract:...` fails on the board | Android's `wpa_ctrl.c` takes a `-g` path without `/` for an android reserved socket, never abstract | `wpa_cli -p /data/vendor/wifi/wpa/sockets -i wlan0` as root for checks; the bundle has its own client |
| `SAVE_CONFIG: FAIL` | the config the bring-up script writes has no `update_config=1` | `SET update_config 1` at session start; `update_config=1` in `net_bringup.sh`'s config |
| after a connect attempt the board stays off its network, the config shows `disabled=1` on the known one | `SELECT_NETWORK` disables the other networks and `SAVE_CONFIG` writes that | `ENABLE_NETWORK all` + `SAVE_CONFIG` after the attempt (success or failure) |
| a wrong password ends in `DISCONNECTED`, never in `FAILED` | the supplicant's events queue while the command runs; a late `CTRL-EVENT-CONNECTED` of the network left ended the attempt | track the attempt by the network id (`[id=N ...]` in the events), not by "an attempt is running" |
| the supplicant restarted by hand dies at once: "ctrl_iface exists and seems to be in use" | the per-interface socket files of the killed instance are still there | `rm -f /data/vendor/wifi/wpa/sockets/{wlan0,p2p-dev-wlan0}` before the start; `killall wpa_supplicant` (the process name has no path) |
| a daemon restarted by hand right after a reboot is replaced again | the bring-up script starts late (after the dlkm loader) and races the hand start; `adb root` is also gone after a reboot | `adb root`, wait a minute after boot, then restart |
| `neverallow check failed ... unix_dgram_socket (connect sendto)` between a core and a vendor domain | Treble's core <-> vendor socket rules, one per direction | `typeattribute X socket_between_core_and_vendor_violators` on both domains, each in its own policy (system_ext / vendor) |
| the bridge logs "taking commands" every second | a gRPC server stream opens lazily and ends at once while the server is not there | log once the first message arrives |
| an RPC call hangs for ever when the server stops answering | `sdv::mw::ClientOptions::default()` (what vsidlc's skeleton uses) sets no deadline | `ClientOptions::builder().timeout(..)`, longer than the slowest answer of the server |
| a long call (a connect waiting for its outcome) holds up the next command | the bridge awaited each call in its stream loop | one task per call (`tokio::spawn`), the answer sent back from the task |
